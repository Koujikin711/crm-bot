# METODI CRM

Telegram-бот для управления лидами с интеграцией WhatsApp (Green API). Два направления: **Медицина** и **Бизнес**. Менеджеры получают лидов, ведут диалоги через «прямой коридор» (сообщения из WA приходят в Telegram и наоборот), закрывают с итогом и получают следующих из очереди.

---

## Возможности

### Для всех
- Регистрация по /start с вводом ФИО.
- Роли: владелец, админ, менеджер. Сферы: медицина (med), бизнес (biz).
- Поиск лида по номеру или ФИО (для тех, у кого есть доступ).

### Один лид в одни руки
- Новый лид назначается только свободному менеджеру: `is_busy = 0` и нет лидов в статусах `active` или `chatting` по его направлению.
- Если все менеджеры сферы заняты — лид сохраняется со статусом `pending`; при «Завершить диалог» следующий лид из очереди автоматически назначается освободившемуся менеджеру.

### Прямой коридор (Session Chat)
- По кнопке **✍️ НАПИСАТЬ** лид переходит в статус `chatting`.
- Все сообщения из WhatsApp (текст, голос, фото) автоматически пересылаются менеджеру в Telegram; ответы менеджера уходят в WhatsApp.
- Внизу чата — кнопка **✅ Завершить диалог**. После нажатия выбирается итог (Оплачено / Думает / Отказ / Не ответил), лид закрывается, менеджер освобождается, при необходимости ему приходит следующий лид из очереди.

### Чистый интерфейс
- Сообщения текущей сессии чата сохраняются в `chat_history` и при «Завершить диалог» удаляются из чата; остаётся только финальная карточка-отчёт.
- При переключении разделов **Статистика** ↔ **KPI** старые сообщения удаляются, чтобы не было «простыни».

### Напоминания и контроль
- Если менеджер открыл коридор, но не писал клиенту более 20 минут — бот присылает: «Вы не отвечаете клиенту! Завершите диалог, если закончили».
- Напоминания в WhatsApp клиентам, которым не ответили 24 часа (таджикский текст).

### Медицина
- Запись к врачу (Ганчина), лимиты на день, воскресенье — выходной.
- Оплаты, продление курса, отчёты, нагруженность, статистика лидов, план/KPI.
- При закрытии лида как «Оплатил» и 10-м визите (курс завершён) — кнопка **📞 Предложить Логопеда/Повтор**.

### Бизнес
- Статистика воронки, KPI менеджеров, поступления лидов за период.
- Включение/выключение приёма лидов; админ может включить «Мои лиды» и получать лидов сам.

### Владелец
- Два меню: Медицина и Бизнес.
- Назначение админов, выдача прав владельца, увольнение, планы, загрузка/выгрузка данных, приход, план/KPI.

## Запуск

### Требования
- Python 3.11+
- Токен Telegram-бота, инстансы Green API (бизнес и при необходимости медицина).

### Установка
```bash
pip install -r requirements.txt
```

### Переменные окружения (опционально)
Скопируй `.env.example` в `.env` и заполни значения. Либо задай переменные в системе или в панели Amvera.

| Переменная | Описание |
|------------|----------|
| `API_TOKEN` | Токен Telegram-бота |
| `CRM_DB_PATH` | Путь к SQLite (на Amvera лучше `/data/crm_base.db`) |
| `ID_INSTANCE`, `API_TOKEN_INSTANCE` | Green API — бизнес |
| `API_URL` | Базовый URL Green API для бизнеса |
| `MED_ID_INSTANCE`, `MED_API_TOKEN`, `MED_API_URL` | Green API — медицина |
| `OWNER_ID` | Telegram user_id владельца по умолчанию |

В коде по умолчанию подставлены тестовые значения; для продакшена все секреты лучше вынести в переменные окружения.

### Запуск локально
```bash
python main.py
```

Запускаются: бот (polling), опрос двух инстансов Green API (biz + med), напоминания 24ч, проверка 20 мин без ответа в режиме chatting.

## Деплой на Amvera

1. Репозиторий подключается по инструкции в **DEPLOY.md** (GitHub → вебхук → Amvera).
2. В настройках проекта задай `CRM_DB_PATH=/data/crm_base.db` (или другой путь постоянного тома), чтобы БД не терялась при пересборке.
3. Токены и ключи API задай в переменных окружения в Amvera, не храни в коде.

## База данных (SQLite)

Основные таблицы: `users`, `leads`, `auth_queue`, `settings`, `appointments`, `lead_events`, `reminded_24h`, `follow_up_queue`, `chat_history`, `chat_sessions`. Схема создаётся при первом запуске в `init_db()`.
