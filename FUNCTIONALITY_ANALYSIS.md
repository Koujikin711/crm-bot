Нужно сузить фильтр на 1810 до кнопок только глобального вкл/выкл (см. раздел 4).

## 2. Callback_data: префиксы и риски

| Префикс | Назначение | Ограничение 64 байта |
|---------|------------|----------------------|
| cl_ | Итог звонка (Позвонить) | cl_ + phone[:30] — ок |
| f_s_, f_t_, f_r_, f_n_ | Бизнес: Оплатил/Думает/Отказ/Не ответил | f_x_ + phone — в части мест phone без [:30] |
| med_r_, med_t_, med_p_, med_n_ | Медицина: Отказ/Подумает/Оплатил/Не отвечают | med_x_ + phone — везде phone может быть длинным |
| re_ | Переназначить: список менеджеров или re_phone_uid | re_ + phone[:30] + _ + uid — ок |
| reto_ | Выполнить перенаправление (из «Лиды в работе») | reto_ + phone[:30] + _ + uid — ок |
| reas_ | Кнопка «Перенаправить» в списке «Лиды в работе» | **reas_ + phone без обрезки** — при длинном номере > 64 байт сбой |
| rp_ | Написать (диалог) | rp_ + phone[:30] — ок |
| card_ | Карточка лида из поиска | **f"card_{phone}"[:64]** — обрезка по 64 символам, phone обрезается; в обработчике c.data[5:] — неверный/обрезанный номер |
| wlead_, call_, hist_ | Написать/Позвонить/История из карточки | wlead_/call_/hist_ + phone — в карточке phone уже может быть обрезан из card_ |
| medpkg_ | Выбор пакета (Оплатил) | medpkg_ + phone + _ + i — phone без [:30] |
| bizlead_, medstat_, medinc_, medlead_ | Периоды отчётов | Без номера — ок |
| sp_, giveowner_, medadm_, bizadm_ | План, владелец, админы | Только id — ок |

**Итог:**  
- Для **card_** нужно не обрезать строку по 64 символам, а класть в callback только `phone[:30]` и в обработчике вызывать `get_lead_phone_by_prefix(c.data[5:])`.  
- Для **reas_** в списке «Лиды в работе» использовать `reas_{phone[:30]}` и в обработчике — `get_lead_phone_by_prefix`, иначе при длинном номере callback превысит лимит и перенаправление сломается.

## 3. Поток лидов (путь и статусы)

### 3.1 Создание лида

- **Бизнес:** первое сообщение в WA → сразу создаётся лид (name из текста или «Клиент»), `created_at` ставится. Свободный менеджер — `active` + назначение, иначе `pending`.
- **Медицина:** первое сообщение → auth_queue (step=1), просят имя. Второе сообщение (имя) → создание лида, `created_at`, назначение или pending.

### 3.2 Переходы статусов

- **pending** → **active:** назначение свободному менеджеру (`try_assign_queued_lead_to_manager` при освобождении или при первом сообщении).
- **active** → **chatting:** менеджер нажал «Написать» (rp_) или «Начать диалог» и ввёл номер; создаётся/обновляется `chat_sessions`, очищается chat_history по этому лиду.
- **chatting** → **active:** без явного перехода в коде; при «Завершить диалог» показываются итоги (med_* / f_*), затем статус меняется в зависимости от кнопки.
- **chatting/active** → **thinking:** НЕ ОТВЕЧАЮТ / НЕ ОТВЕТИЛ (med_n_, f_n_); сессия удаляется, is_busy=0, лид в дожим.
- **chatting/active** → **closed:** Оплатил (med_p_ → пакет → сумма, f_s_), Отказ (med_r_ + комментарий, f_r_), Думает/Подумает (med_t_, f_t_ → follow_up_queue или просто смена статуса в зависимости от логики).

### 3.3 Где что может сломаться

- **Владелец не выбрал меню:** «📋 Лиды в работе» использует `owner_current_sphere`. Если владелец не нажимал 🏥/💼, sphere = None → показывается список по бизнесу. Ожидание «медицина» или «оба» может не совпасть.
- **Один номер в двух сферах:** лид привязан к одному direction; сообщение из другого инстанса WA игнорируется (lead_dir != instance_name). Объединить два направления для одного номера нельзя.
- **Два менеджера и один лид:** при перенаправлении (reto_) старый менеджер теряет сессию (delete chat_sessions + chat_history_delete_messages), новый получает уведомление — конфликта нет. Но если владелец перенаправил лид, а старый менеджер ещё не обновил чат, он может попытаться отправить сообщение — тогда `reply_done` берёт target из `chat_sessions`; у старого сессии уже нет, target будет None и сообщение никуда не уйдёт (защита есть).

## 4. FSM: состояния и пересечения

- **Form.waiting_for_reply** — диалог с клиентом; все сообщения уходят в WA, кнопка «Завершить диалог» обрабатывается в reply_done.
- **Form.refuse_comment_med** — после нажатия «Отказ» в медицине; следующий текст = комментарий, пишется в comment.
- **Form.closing_sphere / Form.closing_comment** — после итога звонка в бизнесе (f_s_/f_t_/f_r_), ввод сферы и комментария.
- **Form.med_paid_sum** — после «Оплатил» и выбора пакета в медицине; ввод суммы.
- **Form.med_payment_phone / Form.med_payment_sum** — админ: «💰 Оплаты», ввод номера и суммы.
- **Form.lead_search_query** — после «🔍 Поиск лида»; ввод номера/имени, затем state.clear().
- **Form.new_chat_phone** — после «💬 Начать диалог»; ввод номера, затем переход в waiting_for_reply.

Риск: если пользователь в состоянии (например, refuse_comment_med) нажимает «◀ Назад» или «🏥 МЕДИЦИНА», состояние не сбрасывается в этих обработчиках — остаётся старый state. При следующем действии может сработать обработчик по state (например, следующий текст попадёт в комментарий отказа). Рекомендация: в обработчиках «Назад» и смены раздела при необходимости вызывать `state.clear()`.

## 5. Расположение кнопок и взаимное влияние

- **Главное меню (get_main_menu):** разное для owner / admin med / admin biz / manager biz / manager med. Кнопки не дублируются между ролями в одном меню.
- **Owner:** после 🏥/💼 показывается подменю (get_owner_med_menu / get_owner_biz_menu). В медицине есть и «📂 Загрузка данных» (в тексте меню — имеется в виду «Выгрузка (мед)» и «Загрузка данных» для бизнеса в разных меню), дублирования одной кнопки под одно действие нет.
- **Резерв «Завершить диалог»:** finish_dialog_fallback срабатывает только если state != Form.waiting_for_reply, и использует chat_sessions — не мешает основному сценарию.

## 6. Рекомендуемые исправления (кратко)

1. **Кнопка «📥 Мои лиды: ВКЛ/ВЫКЛ»:** заменить `F.text.contains("ЛИДЫ")` на точный список кнопок глобального вкл/выкл, например `F.text.in_(["🟢 ВКЛ ЛИДЫ", "🔴 ВЫКЛ ЛИДЫ"])`, чтобы не перехватывать «📥 Мои лиды: ВКЛ/ВЫКЛ».
2. **card_:** в поиске использовать `callback_data=f"card_{phone[:30]}"` (без обрезки всей строки по 64); в lead_card_show вызывать `get_lead_phone_by_prefix(c.data[5:])` и работать с полным номером.
3. **reas_:** в списке «Лиды в работе» использовать `callback_data=f"reas_{phone[:30]}"`; в reassign_lead_choose получать полный номер через `get_lead_phone_by_prefix(c.data.replace("reas_","").strip())`.
4. **Единообразие callback с phone:** везде, где в callback передаётся номер (med_r_, med_t_, med_p_, med_n_, f_s_, f_t_, f_r_, f_n_, medpkg_), использовать phone[:30] и в обработчиках при необходимости — get_lead_phone_by_prefix, чтобы не превышать 64 байта и не ломать поиск по длинным номерам.
5. **«Назад» / смена раздела:** при переходе в главное меню или смене раздела (🏥/💼) для owner при необходимости вызывать `state.clear()`, чтобы не залипали FSM (refuse_comment_med, closing_comment и т.д.).

После этих правок пути лидов, расположение кнопок и обработка callback станут предсказуемыми, а конфликт «Мои лиды» vs глобальный вкл/выкл лидов исчезнет.
